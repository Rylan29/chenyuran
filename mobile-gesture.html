任务一：事件侦探

一次拖动到底发生了什么

用手机或 DevTools 设备模式依次进行单击、向上拖动、向左快速滑、双指触摸和长按后抬起，典型事件顺序记录如下。N 表示 touchmove 的实际触发次数。

五种操作的事件顺序

操作事件触发顺序（参考）观察结果
单击 touchstart → touchend → mousedown → mouseup → click 0 次 move；有 click
向上拖动 touchstart → touchmove × N → touchend 约 20～40 次；通常无 click
向左快速滑 touchstart → touchmove × N → touchend 约 5～15 次；通常无 click
双指触摸 touchstart（第 1 指）→ touchstart（第 2 指）→ touchmove × N → touchend → touchend 每指各有一次 start/end
长按后抬起 touchstart → 静止等待 → touchend → click 静止时 0 次 move

注：touchmove 次数为参考区间，并非每移动 1px 触发一次。若浏览器接管页面滚动，结尾可能出现 touchcancel；系统弹出长按菜单时，也可能不再产生 click。

三个验收问题

  1. 一次拖动里 touchmove 大约触发多少次，和距离有什么关系？

    普通拖动通常是几十次，具体次数取决于拖动时长、设备采样率和浏览器调度。速度相近时，距离越长，持续时间通常越长，touchmove 越多；同样距离下滑得越快，次数反而可能越少。

  2. click 出现在 touchend 之前还是之后？

    之后。单击的常见顺序是 touchstart → touchend → mousedown → mouseup → click，其中兼容鼠标事件是否出现会因浏览器和页面设置略有差异。

  3. 如果把 touchend 换成 touchcancel，会发生什么？

    正常抬手仍触发 touchend，因此原来的结束逻辑不会执行；只有浏览器接管滚动、系统手势打断等异常情况才触发 touchcancel。正确做法是同时监听：touchend 正常完成，touchcancel 清理状态并复位。
